# Implementation plan

## Strategy

Use the existing Architect integration as the structural precedent while preserving the project's single canonical Agent model. Add a Software Engineer role pack and seven ordinary Markdown artifacts that the current generic Web artifact UI can execute, revise, and review.

## Vertical slice

1. Initialize a new project and receive a client-native Software Engineer Agent plus self-contained role workflow, references, and templates.
2. Create a Run and resolve all engineering evidence to deterministic safe Run-scoped paths.
3. Execute implementation with confirmed-scope code/test writes while protecting role resources and unselected registered artifacts.
4. Review all seven documents in the Web and reject approval when AC coverage, isolation, seven-lens review, security escalation, or provenance is incomplete.
5. Backfill the same files into the registered FE-cc project so its ready implementation phase can be tested without reinitialization.

## Constraints

- No new dependency, DB migration, phase, role, or duplicate client Skill.
- `implementation-notes` remains the stable engineering index and Tester handoff.
- Replay packets remain conditional incident evidence and are not a required success artifact.
- Real independent test isolation must be recorded; fake mode cannot become proof of a passing engineering gate.

## Verification

- Independent Tier A test author receives this delta and public behavior only.
- Root initializer tests cover installed files and canonical rendering.
- Platform checks cover definition compatibility, path scoping/pinning, runner boundaries, Web labels/selection, and approval validation.
- Full root/platform tests, typechecks, and builds run before handoff.
